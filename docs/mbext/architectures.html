Supported architectures¶

The table below lists every Hugging Face architecture that modelbuilder.builder.create_model() can convert, together with the builder class that handles it. It is generated automatically at documentation build time by parsing the dispatch chain of create_model (see modelbuilder.architectures.list_supported_architectures()), so it is always in sync with the code.

The example model IDs are a static, non-exhaustive selection favoring the model families that introduced each architecture in Transformers. An empty cell means no example is recorded, not that the architecture is unsupported. These examples do not guarantee support for every checkpoint variant, modality, or export option; the export restrictions documented below still apply.

To obtain the IDs without downloading models or importing Transformers:

from modelbuilder.architectures import (
    list_supported_architectures,
    list_supported_model_ids,
)

model_ids = list_supported_model_ids()
for architecture in list_supported_architectures():
    print(architecture.name, architecture.model_ids)

The architecture name is the value of config.architectures[0] in the Hugging Face config.json. To convert a model of a given family, point -m or -i at a checkpoint whose config declares that architecture.

51 architectures are currently supported.

SmolVLM image inputs¶

HuggingFaceTB/SmolVLM-256M-Instruct exports its text decoder by default. Set multimodal=True (CLI: --extra_options multimodal=true) to also export vision_encoder.onnx and embedding.onnx. Adapter export and --reuse-weights are not supported for SmolVLM.

The vision encoder takes one normalized, square crop at the checkpoint’s configured image size as pixel_values [1, channels, height, width]. Use the Hugging Face processor for image splitting, resizing, normalization and prompt construction. Masked padding and variable-size crops are not supported by this fixed-size vision export. Encode each crop separately and concatenate image_features in prompt order.

Pass input_ids [1, sequence] and image_features [image_tokens, hidden] to the embedding model; it replaces the image placeholders in place. Feed its inputs_embeds output to the decoder. During cached decoding, pass an empty [0, hidden] image-feature array to the embedding model.

ONNX Runtime GenAI can run the three components using the exported phi3v configuration and explicit preprocessed inputs: supply pixel_values and num_image_tokens through NamedTensors, then append the expanded prompt tokens. This does not provide a SmolVLM-specific raw-image processor in GenAI.

Qwen2.5-Omni video inputs¶

Export with multimodal=True to produce the shared image/video vision encoder, audio encoder, embedding model, and thinker decoder. For direct ONNX Runtime inference with multimodal temporal/spatial positions, also set use_3d_position_ids=True (CLI: --extra_options multimodal=true use_3d_position_ids=true). The default decoder still accepts 2-D position IDs for existing callers. With the 3-D option, vision frame_ids and window_ids are required inputs; without it, they retain their single-frame/window defaults.

The Hugging Face processor supplies pixel_values_videos and video_grid_thw. Prepare the vision feeds as follows:

from modelbuilder.helpers.vision_helper import prepare_qwen25_omni_vision_inputs

feeds = prepare_qwen25_omni_vision_inputs(
    pixel_values_videos, video_grid_thw, thinker_config.vision_config
)
video_features = vision_session.run(["image_features"], feeds)[0]

The helper accepts NumPy arrays in processor patch order. It computes vision RoPE frequencies and frame/window IDs, preventing attention across separate frames or spatial windows. A temporal grid entry counts groups of temporal_patch_size raw frames. The same helper supports images and multiple videos with different spatial dimensions.

Pass the resulting features to embedding.onnx through image_features; this existing input is shared by images and videos. For a mixed prompt, arrange the feature rows in the order that image/video placeholders occur in input_ids. audio_features is unchanged; use an empty [0, hidden_size] array when audio is absent. Modality token IDs come from the checkpoint config, including video_token_id / video_token_index.

Feed the embedding output to model.onnx. With use_3d_position_ids=True, provide position_ids of shape [3, batch, sequence], computed using the thinker’s get_rope_index with the original grids, video timing (second_per_grids), and any audio metadata. Subsequent decoding positions must account for the returned RoPE deltas.

ONNX Runtime GenAI video generation¶

Video-only prompts can also run through ONNX Runtime GenAI 0.15.2 or later with explicit preprocessing. Export with use_3d_position_ids=True and overlay the default phi3v configuration with Qwen-VL position handling:

import json
import numpy as np
import onnxruntime_genai as og

config = og.Config(output_dir)
config.overlay(json.dumps({
    "model": {
        "type": "qwen2_5_vl",
        "image_token_id": thinker_config.image_token_id,
        "video_token_id": thinker_config.video_token_id,
        "vision_start_token_id": thinker_config.vision_start_token_id,
        "vision": {"tokens_per_second": thinker_config.position_id_per_seconds},
    }
}))
model = og.Model(config)
params = og.GeneratorParams(model)
params.set_search_options(do_sample=False, max_length=input_ids.size + 3)
generator = og.Generator(model, params)
tensors = og.NamedTensors()
for name, value in feeds.items():
    tensors[name] = value
merge = thinker_config.vision_config.spatial_merge_size
tensors["num_image_tokens"] = np.array(
    [np.prod(video_grid_thw, axis=1).sum() // merge**2], dtype=np.int64
)
tensors["video_grid_thw"] = np.asarray(video_grid_thw, dtype=np.int64)
tensors["second_per_grid_ts"] = np.asarray(second_per_grids, dtype=np.float32)
generator.set_inputs(tensors)
generator.append_tokens(input_ids)
while not generator.is_done():
    generator.generate_next_token()

GenAI runs the vision encoder, embedding model, and cached decoder; it does not merely consume externally computed logits. The native 3-D export makes frame/window inputs required because GenAI does not forward overridable initializer inputs. The fp32/fp16 test_video_*_cpu_genai tests compare positions, embeddings, logits, and generated tokens against PyTorch.

This explicit-input setup does not provide automatic raw-video processing or Omni audio/video interleaving. GenAI’s Qwen-VL positions round temporal coordinates whereas Omni truncates them; use timings for which second_per_grids * position_id_per_seconds is integral for parity. Use direct ONNX Runtime and Omni’s get_rope_index for other timings or audio/video interleaving. The default phi3v configuration is unchanged.

Adding a new architecture¶

Support for a new family is added by:

  1. implementing a Model subclass in modelbuilder/builders/ (usually subclassing an existing builder and overriding the few pieces that differ);

  2. adding an elif config.architectures[0] == "<Name>ForCausalLM": branch to create_model() that instantiates the builder;

  3. adding a fast test under tests/fast that converts a tiny random-weight model and checks the discrepancies.

Once the branch is added, this page picks up the new architecture automatically.
