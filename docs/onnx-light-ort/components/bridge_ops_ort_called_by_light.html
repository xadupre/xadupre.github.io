onnxruntime custom operators called by onnx-light#

Run trusted ORT-compatible custom-op libraries in the standalone onnx-light runtime, without installing or loading ONNX Runtime. This project is implemented.

Design#

onnx_light_ort::bridge_ops_ort_called_by_light is a shared library depending only on common_ort_to_light and the platform loader. It does not install, load or link ORT. onnx_light_ort.CustomOpSessionOrtCalledByLight accesses its small C ABI through ctypes from the source checkout. Its model objects come from onnx_light.onnx bindings built in the same tree, not the onnx package; no project artifact is installed into site-packages. Execution uses a real onnx-light RuntimeSession and context-local KernelBase factory, not a substitute Python implementation.

C++ consumers link only onnx_light_ort::bridge_ops_ort_called_by_light and include onnx_light_ort/bridge_ops_ort_called_by_light/host.h. The target publishes the repository and ORT API include paths; its implementation libraries remain private. A consumer test builds without the test helper’s additional include paths to verify this contract.

Requirements#

Build with a C++20 compiler, CMake 3.28 or newer and ONNX_LIGHT_ORT_BUILD_HOST=ON. CMake supplies onnx-light and pinned ORT headers; no ORT runtime is needed. Use only explicitly selected, trusted native plugins matching the audited API-18 profile below. Python callers need NumPy, ml-dtypes and matching onnx_light.onnx bindings from build/python. See Development for source-build instructions.

Initial audited profile#

This is not a general ORT compatibility claim. Plugins are trusted executable code, loaded from this package’s library or an explicit caller-supplied path resolved before loading. Models never select a library. They must be audited against this API subset; unsupported function-table slots are null and must not be called. Arbitrary plugin binaries are not safe to probe for compatibility by executing them.

The host accepts only API-18 descriptors, one required CPU input and output of matching float16, bfloat16, float32 or float64 type, a custom-domain opset import, and status-returning CreateKernelV2 and KernelComputeV2 callbacks with KernelDestroy. The initial model must contain exactly one custom node, with distinct graph input and output, no initializers and no local functions. Model data is limited to 16 MiB and each runtime tensor to 64 MiB, with rank at most 16 and checked nonnegative dimension products. Scalars and empty tensors are supported. The Python wrapper checks serialized model size before parsing bytes and input size and rank before copying arrays. These checks raise ValueError; native validation remains in place for C callers.

Registration rejects missing descriptors, unsupported devices or types, duplicate registrations for the same domain/name/type, incompatible opsets, optional/variadic arguments, alias callbacks and shape-inference callbacks. Concrete type overloads are selected by the model’s tensor type; generic UNDEFINED type descriptors are not supported. Legacy callbacks, EPs, logging/configuration, general allocator APIs and the remaining roadmap functions are not implemented. Output shapes are determined at execution.

Kernels are initialized lazily once per session node and retained across changing input shapes. Every call reads the current runtime context. The Python wrapper serializes runs and close operations, copies inputs to protect caller-owned arrays from the API’s mutable data accessor, and returns independent NumPy output copies. Output buffers are host-owned. This initial Python interface does not claim zero-copy execution.

LightOrtRunTyped accepts a raw input pointer, its ONNX element type and element count, and returns raw output storage of the same type. It checks the model type, element alignment and dtype-dependent byte limit before reading the input. The original LightOrtRun C ABI remains available for float32 and rejects models of another type. The Python wrapper uses the typed entry point, accepts NumPy float16/float32/float64 and ml_dtypes.bfloat16 arrays, and rejects arrays whose dtype differs from the model instead of converting them.

close() and the context-manager protocol release kernels before unloading the plugin. A finalizer also releases abandoned sessions. Registration and compute errors propagate as Python exceptions; there is no ORT fallback.

C ABI contract#

There are two C ABI boundaries: the ORT-compatible interface implemented for plugins, and the small session interface exported to C++ and Python callers. Neither requires an ORT runtime.

The host loads the plugin’s exported RegisterCustomOps with this signature:

extern "C" OrtStatus *ORT_API_CALL
RegisterCustomOps(OrtSessionOptions *options, const OrtApiBase *api_base);
ORT-compatible plugin interface#

API / descriptor

Standalone host behavior

OrtApiBase

Supplies its own table. GetApi accepts only version 18; GetVersionString identifies the standalone host.

CreateCustomOpDomain, CustomOpDomain_Add, AddCustomOpDomain

Record plugin domains and descriptors. Ownership stays with the plugin; they must outlive every referencing session.

OrtCustomOp

Validate against the audited profile above; select by domain, name, opset and tensor type.

CreateKernelV2

Call once on first execution. Supply KernelInfoGetAttribute_float for construction attributes.

KernelComputeV2

Call on each run with an adapted OrtKernelContext. Map input, output, type/shape and data access to onnx-light CPU tensors.

Tensor metadata

Release with ReleaseTensorTypeAndShapeInfo.

Values and tensor buffers

Borrowed; the plugin must not free them.

KernelDestroy

Release retained state before unloading the plugin library.

Callback results

nullptr means success; otherwise return an owned OrtStatus *. Never let C++ exceptions cross the ABI. The host reads errors with GetErrorMessage and frees statuses with ReleaseStatus.

Unsupported API slots

Null, not fallback implementations. See Shared support for hosting ORT-compatible plugins for supported entries.

Application session interface#

Export / result

Caller contract

LightOrtCreateSession

Pass a trusted library path and serialized ONNX bytes. Load the plugin, parse the model and return an opaque session.

LightOrtRunTyped

Borrow element-aligned input storage for the call. Return session-owned output data and shape pointers; copy before the next run or release.

LightOrtRun

Float32-only convenience entry point.

LightOrtReleaseSession

Destroy the session, its kernels and then the library. Serialize runs and release operations on each session; never race them.

Creation / execution result

nullptr means success; a non-null status means failure.

LightOrtGetErrorMessage

Read a borrowed message from a failure status.

LightOrtReleaseStatus

Free the failure status after reading its message.

Tests and example#

The independent examples/custom_ops/ort_custom_ops.cc implements ort_custom_ops::LeakyRelu using only pinned ORT headers and its own numerical code, without linking onnx-light. This independent example remains float32-only. Native tests execute it under the standalone host, including scalar/empty inputs and API negotiation failure. Python tests check changing shapes, read-only and noncontiguous inputs, retained kernel state, independent sessions and outputs, close ordering, missing attributes, unsupported graphs, versions, names and dtypes. They assert that neither ORT nor the onnx package was imported.

Run ctest --test-dir build -L bridge_ops_ort_called_by_light --output-on-failure. Enable ONNX_LIGHT_ORT_TEST_PYTHON=ON for the Python cases. When the plugin target is enabled too, an additional Python suite loads the actual onnx_light::LeakyRelu and onnx_light_cpu::Log custom ops in all four types through the same standalone host. These share numerical cases with the real-ORT suite: SIMD tails, changing shapes, scalars, empty tensors, near-one and subnormal inputs, non-finite values, read-only inputs and recovery after type/rank errors. The host remains generic; it does not link the outgoing bridge or import ORT to execute this kernel. See onnxruntime custom operators called by onnx-light for the executable example and Development for build and environment setup.

Python snippet#

After building the host and independent example plugin, set ONNX_LIGHT_ORT_INCOMING_CUSTOM_OP_LIBRARY to the plugin’s absolute path. ONNX_LIGHT_ORT_HOST_LIBRARY optionally selects the host library explicitly. This excerpt constructs a model and runs the trusted custom operator without ORT:

import os

import numpy
import matplotlib.pyplot as plt
from onnx_light.onnx import TensorProto, checker, helper

from onnx_light_ort import CustomOpSessionOrtCalledByLight

# %%
# This first host profile accepts one float32 CPU custom node. Unsupported
# signatures, opsets and API versions fail explicitly.
model = helper.make_model(
    helper.make_graph(
        [helper.make_node("LeakyRelu", ["X"], ["Y"], domain="ort_custom_ops", alpha=0.125)],
        "ort-custom-op-in-onnx-light",
        [helper.make_tensor_value_info("X", TensorProto.FLOAT, ["N"])],
        [helper.make_tensor_value_info("Y", TensorProto.FLOAT, ["N"])],
    ),
    opset_imports=[helper.make_opsetid("ort_custom_ops", 1)],
    ir_version=9,
)
checker.check_model(model)

# %%
# This independent plugin is explicitly selected: native plugins execute trusted
# code and are never discovered from the model. The host defaults to our build.
host = os.environ.get("ONNX_LIGHT_ORT_HOST_LIBRARY")
library = os.environ["ONNX_LIGHT_ORT_INCOMING_CUSTOM_OP_LIBRARY"]
values = numpy.array([-4, -1, 0, 2], dtype=numpy.float32)
with CustomOpSessionOrtCalledByLight(model, library=library, host_library=host) as session:
    result = session.run(["Y"], {"X": values})[0]
    numpy.testing.assert_array_equal(result, [-0.5, -0.125, 0, 2])
    other = numpy.array([1, -2], dtype=numpy.float32)
    numpy.testing.assert_array_equal(
        session.run(None, {"X": other})[0], numpy.where(other < 0, other * 0.125, other)
    )
print("ORT custom op called by onnx-light:", result)

C++ example#

The C++ custom operator below is the independent plugin consumed by the Python snippet. It implements registration, an API-18 OrtCustomOp descriptor and the retained LeakyRelu kernel using only ORT headers, with no ORT or onnx-light link dependency. Its two extra counter exports are used only by tests.

Build the plugin and host, then execute the native C++ host tests:

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release \
  -DONNX_LIGHT_ORT_BUILD_HOST=ON -DONNX_LIGHT_ORT_BUILD_EXAMPLES=ON
cmake --build build --parallel "$(nproc)"
ctest --test-dir build -L bridge_ops_ort_called_by_light --output-on-failure

The native test constructs the same custom-domain model, creates a session through LightOrtCreateSession and executes it with LightOrtRun. For application integration, link onnx_light_ort::bridge_ops_ort_called_by_light and include its host.h, not the private compatibility-table implementation.

// SPDX-License-Identifier: Apache-2.0

#include "onnxruntime_c_api.h"

#include <array>
#include <atomic>
#include <exception>
#include <memory>
#include <mutex>
#include <new>
#include <vector>

#ifdef _WIN32
#define CUSTOM_OP_EXPORT __declspec(dllexport)
#else
#define CUSTOM_OP_EXPORT __attribute__((visibility("default")))
#endif

namespace {

std::atomic<int> live{0};
std::atomic<int> created{0};

struct Kernel {
  const OrtApi *api;
  float alpha;
};

struct LeakyRelu : OrtCustomOp {
  LeakyRelu() : OrtCustomOp{} {
    version = 18;
    GetName = [](const OrtCustomOp *) { return "LeakyRelu"; };
    GetExecutionProviderType = [](const OrtCustomOp *) -> const char * { return nullptr; };
    GetInputTypeCount = GetOutputTypeCount = [](const OrtCustomOp *) -> size_t { return 1; };
    GetInputType = GetOutputType = [](const OrtCustomOp *, size_t) {
      return ONNX_TENSOR_ELEMENT_DATA_TYPE_FLOAT;
    };
    GetInputCharacteristic =
        GetOutputCharacteristic = [](const OrtCustomOp *, size_t) { return INPUT_OUTPUT_REQUIRED; };
    GetInputMemoryType = [](const OrtCustomOp *, size_t) { return OrtMemTypeDefault; };
    GetStartVersion = GetEndVersion = [](const OrtCustomOp *) { return 1; };
    CreateKernelV2 = [](const OrtCustomOp *, const OrtApi *api, const OrtKernelInfo *info,
                        void **out) -> OrtStatus * {
      float alpha = 0;
      if (OrtStatus *status = api->KernelInfoGetAttribute_float(info, "alpha", &alpha))
        return status;
      auto *kernel = new (std::nothrow) Kernel{api, alpha};
      if (kernel == nullptr)
        return api->CreateStatus(ORT_FAIL, "Cannot allocate LeakyRelu kernel.");
      *out = kernel;
      ++live;
      ++created;
      return nullptr;
    };
    KernelDestroy = [](void *state) {
      delete static_cast<Kernel *>(state);
      --live;
    };
    KernelComputeV2 = [](void *state, OrtKernelContext *context) -> OrtStatus * {
      const auto &kernel = *static_cast<Kernel *>(state);
      const OrtApi &api = *kernel.api;
      const OrtValue *input = nullptr;
      OrtStatus *status = api.KernelContext_GetInput(context, 0, &input);
      if (status)
        return status;
      OrtTensorTypeAndShapeInfo *info = nullptr;
      status = api.GetTensorTypeAndShape(input, &info);
      if (status)
        return status;
      size_t rank = 0;
      status = api.GetDimensionsCount(info, &rank);
      std::array<int64_t, 16> dimensions{};
      size_t count = 0;
      if (!status && rank > dimensions.size())
        status =
            api.CreateStatus(ORT_INVALID_ARGUMENT, "LeakyRelu supports at most 16 dimensions.");
      if (!status)
        status = api.GetDimensions(info, dimensions.data(), rank);
      if (!status)
        status = api.GetTensorShapeElementCount(info, &count);
      api.ReleaseTensorTypeAndShapeInfo(info);
      if (status)
        return status;
      OrtValue *output = nullptr;
      status = api.KernelContext_GetOutput(context, 0, dimensions.data(), rank, &output);
      if (status)
        return status;
      void *input_data = nullptr;
      void *output_data = nullptr;
      status = api.GetTensorMutableData(const_cast<OrtValue *>(input), &input_data);
      if (!status)
        status = api.GetTensorMutableData(output, &output_data);
      if (status)
        return status;
      for (size_t i = 0; i < count; ++i) {
        const float value = static_cast<const float *>(input_data)[i];
        static_cast<float *>(output_data)[i] = value < 0 ? kernel.alpha * value : value;
      }
      return nullptr;
    };
  }
};

struct Domain {
  const OrtApi *api = nullptr;
  LeakyRelu op;
  OrtCustomOpDomain *handle = nullptr;
  ~Domain() {
    if (handle)
      api->ReleaseCustomOpDomain(handle);
  }
};

} // namespace

extern "C" CUSTOM_OP_EXPORT OrtStatus *ORT_API_CALL RegisterCustomOps(OrtSessionOptions *options,
                                                                      const OrtApiBase *base) {
  const OrtApi *api = base->GetApi(18);
  if (api == nullptr)
    return base->GetApi(1)->CreateStatus(ORT_NOT_IMPLEMENTED, "LeakyRelu requires API 18.");
#ifdef CUSTOM_OP_UNSUPPORTED_API
  if (base->GetApi(19) == nullptr)
    return api->CreateStatus(ORT_NOT_IMPLEMENTED, "Custom op requires unavailable API 19.");
#endif
  try {
    static std::mutex mutex;
    static std::vector<std::unique_ptr<Domain>> domains;
    const std::lock_guard<std::mutex> lock(mutex);
    for (const auto &domain : domains) {
      if (domain->api == api)
        return api->AddCustomOpDomain(options, domain->handle);
    }
    auto domain = std::make_unique<Domain>();
    domain->api = api;
    if (OrtStatus *status = api->CreateCustomOpDomain("ort_custom_ops", &domain->handle))
      return status;
    if (OrtStatus *status = api->CustomOpDomain_Add(domain->handle, &domain->op))
      return status;
    domains.push_back(std::move(domain));
    return api->AddCustomOpDomain(options, domains.back()->handle);
  } catch (const std::exception &error) {
    return api->CreateStatus(ORT_FAIL, error.what());
  }
}

extern "C" CUSTOM_OP_EXPORT int CustomOpLiveKernels() { return live.load(); }
extern "C" CUSTOM_OP_EXPORT int CustomOpCreatedKernels() { return created.load(); }

Shared support for hosting ORT-compatible plugins#

onnx_light_ort::common_ort_to_light is a static library exposing the initial audited CPU custom-op subset of OrtApi over onnx-light tensors. It supplies opaque adapters for statuses, registration domains, kernel attributes, values and contexts. onnxruntime custom operators called by onnx-light owns loading, descriptor selection and the session/kernel/library lifecycle. The EP bridge remains unimplemented.

OrtApiBase::GetApi accepts only version 18. The full pinned OrtApi layout is preserved; unsupported slots remain null. Supported entries are:

  • CreateStatus, GetErrorCode, GetErrorMessage, ReleaseStatus.

  • CreateCustomOpDomain, CustomOpDomain_Add, AddCustomOpDomain, ReleaseCustomOpDomain.

  • KernelInfoGetAttribute_float.

  • KernelContext_GetInputCount, KernelContext_GetOutputCount, KernelContext_GetInput, KernelContext_GetOutput.

  • GetTensorTypeAndShape, ReleaseTensorTypeAndShapeInfo, GetTensorElementType, GetDimensionsCount, GetDimensions, GetTensorShapeElementCount, GetTensorMutableData.

  • GetTensorMemoryInfo, MemoryInfoGetDeviceType.

These functions implement dense float16, bfloat16, float32 and float64 CPU values. Type queries report the actual tensor type, and output allocation uses the selected descriptor’s output type. Shape and dtype-dependent byte counts are checked before allocating outputs. The component is independent of the outgoing common library and never loads ORT. tests/ort_test_host.h remains separate test infrastructure for outgoing callback units, not this host.

The dependency-contract smoke test is retained alongside the real incoming fixture tests. Select both using the common_ort_to_light CTest label.
