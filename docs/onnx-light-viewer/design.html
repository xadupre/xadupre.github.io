Application design#

Three layers: VS Code manages sources and panel state, C++ retains and analyzes the model, and the webview draws lightweight snapshots. There is no Python runtime or model-execution service on the default branch. Saving explicitly writes a new model copy; it does not modify the source file. See Implemented features for implemented/in-progress capabilities.

Who owns what?#

  • Local files are streamed on a native worker, omitting large tensor payloads. Virtual sources retain their backing byte buffer; backend cases retain their native owner. Keep borrowed buffers unchanged while a handle is alive. Small available tensor values can be included in previews.

  • Hugging Face downloads enter the persistent cache only after successful native loading and atomic publication. Recovery uses the final local cache path.

  • Graph projection and analysis are synchronous. Only the selected graph is projected, not every descendant.

  • Inline Open/Save submit masked password fields, cleared after submission or closing their panel. Direct editor opening uses a host password prompt. Decryption passwords remain in panel-local reload closures and are never logged.

Failures have dedicated error replies and action-log entries. Shape and metadata analysis first run VerifyModel; invalid connectivity can still be displayed without running either analysis. Update counts compare successful snapshots, not runtime measurements.

What happens after an error?#

Concurrent actions can share one recovery promise. Handlers discard stale results and errors after disposal, model replacement or superseding navigation. A reload can lose prior in-memory inference; local sources must remain available. Logs retain failures across model changes and webview recreation. This recovers caught exceptions, not native process crashes. After fusion, recovery clones the retained edited model instead of reloading the original source, preserving applied rewrites.

How do the panel modules cooperate?#

src/webview.ts loads the local Markdown renderer, the five panel factories, then media/viewer.js, under the same CSP. The viewer creates the controllers with explicit callbacks; no framework or bundler is needed for these modules.

The viewer routes file and fusion replies to their controllers, which reject superseded request IDs. A replacement graph resets inspector/metadata displays, clears operator documentation, and invalidates file listings and fusion previews. Metadata presentation belongs to its panel; tensor highlighting and selection remain in the viewer. See Operator and tensor inspection and Zoom, navigation and moving nodes for the user-facing behavior.

How does the native split preserve ownership?#

native/addon.cc only registers exports. model.cc assembles the retained handle from graph methods and the serialization/fusion method factories. The focused translation units share narrow declarations, not global model state; workers and implementation helpers remain private to their source file.

Each method closure captures the shared StoredModel, so even a detached method keeps its source alive. Clones and fusion results retain the previous StoredModel as backing; virtual-file models retain their byte array and backend models retain their test case. Member declaration order ensures that the parsed model is destroyed before these backing owners.

Save and fusion workers retain their source and operate on a SharedCopy snapshot, restoring omitted payloads before use. This is not a promise of bounded-memory saving or fusion: those operations can materialize weights. Graph projection and analysis remain synchronous; splitting translation units does not move them onto workers. See Opening models and Fusion patterns for the action semantics.

Contracts worth keeping#

  • NativeModel.graph(inferShapes?, path?) projects one graph; requesting inference updates the enclosing model first. metadata(path?) returns a separate, read-only analysis snapshot. serialize and serializeFiles save the retained model as a new plain, encrypted or external-weight copy.

  • Fusion materializes weights in an independent native snapshot. Selected patterns apply together against original node indices; overlapping candidates are rejected. Graph replacement or cancellation invalidates previews. Replacement previews share one trial builder per pattern without rewriting the matched graph. External-weight reuse indexes candidates by name, element type and dimensions before comparing their payloads and checking backing files.

  • GraphPath uses validated indices, not potentially duplicate names. Functions use their own imports and formal names, not the caller’s weights; nested graph attributes can capture enclosing values.

  • Tensor dimensions remain strings. [] means scalar, null means unknown rank; non-tensor types can omit the shape.

  • Model text arrives through messages, not HTML interpolation. Operator docs use bundled Markdown rendering with raw HTML disabled, HTTP(S)-only links and no remote image fetching.

  • Large graphs attach only visible SVG details. Fit uses batched paths; search indexes all nodes, including those without a current DOM element. Moving nodes updates only their groups and incident edges.
