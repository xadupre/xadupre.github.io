graph_layout.h#

GraphLayout binds a live GraphProto or FunctionProto without taking ownership or copying the body. Call Load before editing and Persist before serializing. The bound proto must outlive the layout; geometry and route queries return borrowed views, unlike the Python snapshot API.

See Incremental graph layout for scope coordinates, incremental guarantees, persisted metadata and folded-node rendering rules.

Alias that makes onnx-light headers compatible with code that references ONNX_LIGHT_NAMESPACE (the macro used in the standard onnx package).

Set to ONNX_LIGHT_NAMESPACE so both names resolve to the same namespace.

Symbol-visibility attribute for the public onnx-light C++ API.

Maps the upstream compatibility macro to onnx-light’s explicit proto ABI annotation. This keeps declarations from vendored ONNX headers visible when lib_onnx_proto uses hidden visibility by default.

Namespace alias so that ONNX C++ code (and consumers such as onnxruntime) that refers to the literal onnx namespace — rather than the ONNX_NAMESPACE macro — resolves to the onnx-light namespace. The standard onnx package lives in namespace onnx; onnx-light uses onnx_light (via ONNX_LIGHT_NAMESPACE), so this alias keeps onnx-light a true drop-in. It is only introduced when the onnx-light namespace differs from onnx.

class GraphLayout#
#include <graph_layout.h>

Maintains incremental positions, routes and child layouts for a live graph or function.

Layout algorithm:

  • Assigns stable scope-local IDs and indexes value producers, consumers and outer captures.

  • Loads child scopes or validated persisted summaries; fits container boxes to child bounds.

  • Validates saved geometry and signatures; infers missing sizes from labels and ports.

  • Expands edit seeds through their consumers and solves only that affected dependency closure.

  • Processes ready nodes in dependency order, assigning ranks and placing consumers to the right of non-folded producers; cycles receive a diagnostic and a single fallback placement pass.

  • Retains existing positions when constraints permit; otherwise uses producer-port barycenters for vertical placement and shifts boxes downward to clear collisions.

  • Queries an augmented AVL spatial index for collisions; folded Constant boxes occupy no space.

  • Rebuilds affected orthogonal routes in input-port order, including implicit capture ports.

  • Propagates child mutations through owning containers and their affected consumers.

  • Persists IDs, geometry, positioning modes, ranks, signatures and bounded scope summaries.

The caller owns the proto and must keep it alive for the layout’s lifetime. Single-argument constructors only bind it; Load initializes indexes and reuses validated persisted geometry. Subsequent semantic edits must use this API. Direct proto edits require Load before further use. Mutations update affected consumers and owning containers, without rebuilding unrelated scopes.

Coordinates are scope-local, left-to-right and y-down. Node order, value names and operator attributes are not changed for placement. Persist writes namespaced metadata before serialization. Borrowed node/edge/order views should be copied before mutations. Child pointers must be reacquired after Load, Replace or Erase can destroy the corresponding child layout.

void Load(bool recurse = true)#

Rebuilds indexes, assigns missing IDs and validates or computes node geometry.

Clears diagnostics and invalidates child pointers. With recurse=false, reuses valid persisted child summaries; children without usable summaries are loaded directly. Recoverable metadata problems are reported through Diagnostics. Exhausting the ID range throws std::overflow_error.

void Persist(bool recurse = true)#

Writes layout metadata without invalidating child pointers; optionally persists children too.

LayoutNodeId Append(const NodeProto &node)#

Appends a node copy with fresh layout state, updates consumers and returns its new local ID.

LayoutNodeId Insert(size_t index, const NodeProto &node)#

Inserts a node copy with fresh layout state; throws std::out_of_range if index > size.

Shifts existing nodes by swapping owning handles without copying their payloads; node, attribute and subgraph addresses remain valid. The shifting loop takes linear time in the number of shifted nodes, independently of payload size. Layout maintenance is separate; this is not a complexity guarantee for the entire Insert operation.

bool Erase(LayoutNodeId id)#

Removes the node and its children, updating consumers; returns false for an unknown ID.

bool Replace(LayoutNodeId id, const NodeProto &node)#

Replaces the node and child scopes while retaining its ID; returns false for an unknown ID.

bool SetPosition(LayoutNodeId id, double x, double y)#

Pins a node at finite coordinates with magnitude <= 1e9, repairing affected consumers. Returns false for an unknown ID, invalid coordinates, or a rejected dependency/collision constraint; constraint rejection also appends a diagnostic. Folded boxes may overlap.
